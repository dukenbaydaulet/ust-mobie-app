# Backend тапсырмасы: мобильді қосымшаның профиль бөлімі

Жоба: `ust-backend` (Laravel, PHP 8.0, JWT `auth('api')`, DB `admin_ustaz`).
Мобильді қосымша (Flutter) профиль беттері үшін төмендегі endpoint-терді шақырады.

## Басты шарт — сайтқа ешнәрсе тимесін

- Сайт қолданатын бар маршруттарды, контроллерлерді, `FormRequest`-терді және
  валидация ережелерін **өзгертпеңіз**. Мысалы, `ResetPasswordRequest` (`min:8`) сол күйі қалады.
- Жаңа логиканың бәрі тек `api/mobile/...` префиксінің астына, бөлек
  контроллерге жазылады: `app/Http/Controllers/Api/V1/Mobile/`.
- Бар `Route::prefix('mobile')` тобы `routes/api.php` соңында тұр, сонда қосыңыз.
  Авторизация керек маршруттар `jwt.auth` тобының ішінде болуы керек.
- Маршруттар кэште тұр. Деплойдан кейін `php artisan route:cache` міндетті,
  әйтпесе жаңа маршруттар 404 береді.
- Қате мәтіндері қазақша болсын. Қосымша `errors` ішіндегі бірінші хабарды көрсетеді.

## Қателердің ортақ форматы

Валидация қатесі `422` кодымен, Laravel-дің стандарт форматында келеді:

```json
{ "message": "...", "errors": { "password": ["Құпия сөз қате."] } }
```

Қосымша `errors`-тағы бірінші өрістің бірінші хабарын экранға шығарады.
`404` келсе, қосымша «бұл мүмкіндік серверде әлі қосылмаған» деп жазады.
Сондықтан маршрут жоқ болса, басқа код қайтармаңыз.

## 1. Құпия сөзді өзгерту — 4 таңбадан

Локальды нұсқада жазылған. Бар болғаны commit жасап, деплой ету керек.

`POST /api/mobile/profile/password` · `jwt.auth`

Сұраныс денесі:

| өріс | ереже |
|---|---|
| `oldPassword` | міндетті |
| `password` | міндетті, кемінде **4** таңба |
| `passwordConfirm` | міндетті, `password`-пен бірдей |

Логика сайттың `ResetPasswordController::resetPassword` әдісімен бірдей:
1. Қазіргі пайдаланушының `real_password` өрісін `oldPassword`-пен салыстыру.
   Сәйкес келмесе, `422` және `errors.oldPassword = [__('auth.password is incorrect')]`.
2. `password = sha1(жаңа)`, `real_password = жаңа` деп жаңарту.
3. Жауап: `200 {"success": true}`. Жаңа құпия сөзді жауапқа қоспаңыз.

Қате мәтіндері:
- `password.min` → «Құпия сөз кемінде 4 таңбадан тұруы керек.»
- `passwordConfirm.same` → «Құпия сөздер сәйкес келмейді.»

Дайын файлдар (`ust-backend`, әзірге commit жасалмаған):
- `app/Http/Controllers/Api/V1/Mobile/MobileProfileController.php` — жаңа файл;
- `routes/api.php` — `use ...MobileProfileController;` және
  `Route::post('profile/password', [MobileProfileController::class, 'changePassword']);`.

Бұл endpoint серверде болмаса, қосымша ескі `/auth/reset-password`-ке жібереді,
ол 8 таңба талап етеді. Яғни деплой етілмейінше 4 таңбалы құпия сөз сақталмайды.

## 2. Аккаунтты жою

`POST /api/mobile/account/delete` · `jwt.auth`

Сұраныс денесі: `{ "password": "..." }`

Қосымша бұл маршрутты пайдаланушы құпия сөзін енгізіп растағаннан кейін шақырады.
Сәтті жауаптан соң токенді өшіріп, «Аккаунтыңыз жойылды» бетін көрсетеді.

Талаптар:
1. `password` міндетті. Қазіргі пайдаланушының `real_password` өрісімен сәйкес
   келмесе: `422`, `errors.password = ["Құпия сөз қате."]`.
2. Аккаунт жойылғаннан кейін:
   - сол телефон нөмірімен және құпия сөзбен кіру **мүмкін болмауы** керек;
   - бар JWT токен жарамсыз болуы керек (`auth('api')->invalidate()` немесе
     `logout()`);
   - сол телефон нөмірі кейін жаңа аккаунт тіркеуге **бос** болуы керек.
3. Жауап: `200 {"success": true}`.

Іске асыру тәсілін өзіңіз таңдаңыз, тек сайттың бар жұмысын бұзбаңыз.
Ұсынылатын тәсіл — жұмсақ жою (анонимдеу). Пайдаланушы жолын өшірмейді,
сондықтан материалдар, төлемдер және басқа кестелердегі сілтемелер бұзылмайды:
- `tel_num`, `tel_num2`, `email`, `real_password`, `password`, `firebasetoken`,
  `telegram_chat_id`, `img1` өрістерін тазалау немесе бірегей «deleted_<id>»
  мәніне ауыстыру;
- аты-жөнді «Жойылған пайдаланушы» деп ауыстыру;
- `is_blocked = 1`, `blocked_at = now()` қою. Сонда `CheckBlockedUser`
  middleware ескі токенмен келген сұранысты да тоқтатады.

Егер аккаунттың «жойылғанын» «бұғатталғанынан» ажырату керек болса
(мысалы, админкада), бөлек өріс қосуға болады (мысалы, nullable `deleted_at`).
Бұл — `user` кестесіне жаңа баған, яғни сайтпен ортақ DB-ге миграция.
Сондықтан алдымен келісіп алыңыз.

Жою туралы журнал жазған дұрыс: кім, қашан, қай IP-ден жойды.

---

**Күйі:** локальды `ust-backend`-те жазылған (`MobileProfileController::deleteAccount`,
маршрут `routes/api.php`-те, `route:cache` жасалған). Commit пен деплой керек.

## 2а. Сайттағы беттер — бөлек промотта

`ust.kz/privacy` және `ust.kz/account-delete` беттері сайттың фронтендінде
(`ust-new-frontend`) жасалады: `docs/frontend-site-prompt.md`.
Backend-тен жаңа ештеңе керек емес. `ust.kz/account-delete` беті сайтта кірген
пайдаланушының JWT токенімен осы `POST /api/mobile/account/delete` маршрутын
шақырады. Тек ust.kz доменінен келген CORS сұранысы өтетінін тексеріңіз
(сайттың басқа сұраныстары өтіп тұрса, бұл да өтеді).

## 3. Жазылымды тоқтату — қазір қажет емес

Қосымшада «Жазылымды тоқтату» батырмасы әзірге **жасырын**.
Тарифтер бір реттік төлеммен сатылады, автоматты жаңарту жоқ.
Сондықтан бұл endpoint-ті қазір жазудың қажеті жоқ.

Кейін керек болса, қосымша мына маршрутты шақырады:
`POST /api/mobile/subscription/cancel` · `jwt.auth`, денесі бос, жауабы
`200 {"success": true}`. Мағынасы кейін келісіледі.

## 4. Деплойға дайын тұрған бұрынғы өзгерістер

Бұлар `ust-backend`-те жазылып, локальды тексерілген, бірақ production-ға
(`api.ust.kz`) шыққаны расталмаған. Деплой кезінде бірге шығару керек:

- `MobileMaterialController`:
  - іздеу нәтижелерінің сәйкестігі (BOOLEAN mode + relevance бойынша сұрыптау);
  - id=1 «Барлық» санатының өз сүзгісі ретінде жұмыс істеуі
    (`parseFilters >= 1`, `filterCounts`-қа id 1 қосылған).
- `MobileTariffController` — `POST /api/mobile/tariffs/buy` `{ plan: day | month | year }`.

## Тексеру

Деплойдан кейін:
- `php artisan route:list --path=mobile` шығарған тізімде `mobile/profile/password`
  және `mobile/account/delete` болуы керек.
- Тест аккаунтпен мына жағдайларды тексеріңіз:
  - қате ескі құпия сөз → `422`;
  - 3 таңбалы жаңа құпия сөз → `422`;
  - 4 таңбалы құпия сөз → `200`, содан кейін жаңа құпия сөзбен кіру жұмыс істейді;
  - аккаунтты жоюда қате құпия сөз → `422`;
  - дұрыс құпия сөз → `200`;
  - жойылған аккаунттың ескі токенімен `GET /api/auth/user` → `403`;
  - жойылған аккаунттың нөмірі мен құпия сөзімен кіру → сәтсіз;
  - жойылған аккаунттың нөмірімен жаңадан тіркелу → сәтті.
